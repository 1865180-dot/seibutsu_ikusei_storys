# 道の駅の名物づくり（© Irie Kanji）

中2 技術「C 生物育成の技術」用のシナリオ（ノベル）型ゲーム。ミニトマト（作物の栽培）・マダイ（水産生物の栽培）・たまご（動物の飼育）の3題材。1班（または1人）1台のChromebook、1回 約25〜30分。

## ファイル
- `index.html` … 題材えらびの入口
- `tomato.html` … ミニトマト編（作物の栽培）
- `madai.html` … マダイ編（水産生物の栽培）
- `tori.html` … たまご（採卵鶏）編（動物の飼育）
- `photos/` … 資料カード用の写真を入れるフォルダ（名前の一覧は `photos/README.md`）
- `コード.gs` … 提出先の Apps Script（生物育成シミュレーターと共通。「名物づくり」専用シートの処理を追加したもの）

## 公開のしかた
Settings → Pages → Branch を `main` / `(root)` にして保存。

## 提出（スプレッドシート）
- 提出先は、生物育成シミュレーターと同じ Apps Script です（各HTMLの `SUBMIT_URL`）。
- **今のままでも送れます。** その場合は「記録」シートに、種類＝「名物づくり」の行として入ります。
- **専用シート「名物づくり」に分けたいとき**は、記録用スプレッドシートの Apps Script を `コード.gs` の内容に置きかえ、
  「デプロイを管理」→ ✏️ →「新バージョン」→「デプロイ」をしてください（URLは変わりません）。
- 3題材とも同じ提出先に入ります。どの題材かは「シミュレーション名」の列（ミニトマト／マダイ／採卵鶏）で見分けられます。
- 組の数・番号の最大は `CLASSES` / `MAX_NUM` で変えられます。

## 先生用：すべての結末を確認する
URLのうしろに `?teacher=1` をつけると、左上に確認用ボタンが出ます（ステージ1／ステージ2／各場面／各結末へジャンプ）。
生徒に配るURLには付けないでください。（例：`madai.html?teacher=1`）

## 流れ
タイトル → 登録（組・番号・主人公名） → 導入 → ステージ1（社長だけの意見で失敗） → ステージ2（10場面、3人の意見をくらべて選ぶ） → 評価S〜D・結末 → 3人のコメント → ふりかえり・提出（またはステージ2から再挑戦）

## 10場面（ミニトマト）
品種 → 土づくり → pH → 元肥 → 水やり → わき芽かき → 害虫・病気 → 台風 → 収穫のタイミング → 売り方
場面2・3・4・6・7では、3人の意見の前に「資料カード」（図・写真）が出ます。
場面ごとに「学習メモ」（団粒構造・pH・肥料の三要素・IPM・追熟・地産地消 など）が出ます。
前の選択があとの場面に響くところが3か所あります（土→元肥／わき芽→台風／水やり→収穫）。

## 評価のしくみ
4つのメーター（収量・品質・コスト・環境）を、「もうけ・量」「品質」「環境」の3つの軸にまとめ、
合計点と「かたより」で S〜D を決めます。どれか1つに寄ると、評価の上限が下がり、かたよりに合った結末になります。

## 10場面（マダイ）
稚魚えらび → いけすの場所 → 水温と酸素 → 魚の数 → えさやり → えさの種類 → 病気への備え → 赤潮への備え → 出荷のしかた → 売り方
資料カードは場面2・3・6・8。学習メモは、人工種苗・潮通しと日焼け・変温動物・飼育密度・自発給餌・配合飼料・ワクチン・赤潮・活けじめ・水産エコラベル など。
前の選択が響くところ：いけすの場所や水温の観測→魚の数／病気への備え→赤潮／えさやり→出荷。

## 10場面（たまご・採卵鶏）
ヒナえらび → 飼い方 → えさ → 病気の予防 → 光の管理 → 毎日の世話 → 鶏ふんの始末 → 夏の暑さ → 卵の検査と出荷 → 売り方
資料カードは場面2・3・4・5・7・9。学習メモは、品種改良・アニマルウェルフェア・エコフィード・鳥インフルエンザの予防・点灯管理・機械化・鶏ふん堆肥・暑さ対策・検卵・地産地消 など。
前の選択が響くところ：えさや病気の予防→光の管理／鶏ふん→夏の暑さ／毎日の世話→卵の検査。

3題材とも、場面ごとの点の動きと評価のしくみは同じです（どの題材でも、同じむずかしさ）。
